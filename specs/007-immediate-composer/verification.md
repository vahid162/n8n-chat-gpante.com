# شواهد — ۲۰ اکتبر ۲۰۲۶

۶۰ آزمون Node موفق‌اند؛ موارد جدید نوشتن قبل از آماده‌شدن، ارسال زودهنگام دقیقاً یک‌بار با policy معتبر، بستن/بازکردن، شکست اتصال و retry، ویرایش متن شکست‌خورده و بازخوانی پس‌زمینه با حفظ تمرکز بیرون را پوشش می‌دهند. سیاست نامعتبر، نوشتن را باز می‌گذارد ولی هیچ sendMessage یا clear مجازی ایجاد نمی‌کند. PHP settings/appearance/bridge/catalog، پنج تست بسته/انتشار و WPCS نیز موفق‌اند.

Chrome واقعی با WordPress محلی و backend مصنوعی، تاریخچهٔ عمداً کند را قبل از تحویل پاسخ نگه داشت. ورودی همان لحظه فعال و متمرکز و دکمهٔ ارسال با متن فعال بود. ارسال قبل از آمادگی، Enter تکراری و بستن/بازکردن فقط یک loadPreviousSession و سپس یک sendMessage ایجاد کردند؛ بیشترین درخواست هم‌زمان یک بود. reload همان نشست امضاشده را با یک نسخه از سؤال/پاسخ برگرداند. تاریخچهٔ دیررس پیش‌نویس ارسال‌نشده را حفظ کرد. شکست اتصال هیچ ارسال خودکاری نداشت، متن باقی ماند و یک retry صریح، اتصال و سپس ارسال را انجام داد. سه اندازهٔ صفحه، صفر violation محدود و صفر خطای runtime تأیید شدند؛ هیچ تماس مدل انجام نشد.

رگرسیون مرورگرِ موجود نیز با همان WordPress واقعی و backend مصنوعی اجرا شد: ارسال، لینک امن، reload، خطای ارسال و retry، سه اندازه، تأیید/لغو/موفقیت clear و بستن با Escape، همگی با صفر خطای runtime موفق بودند.

برای آزمون‌های مرورگرِ منتظرِ پایان درخواست، معیار آمادگی از disabled ورودی به aria-busy=false در log تغییر کرد؛ فعال‌بودن ورودی دیگر نشانهٔ پایان اتصال نیست. واحدها timeout هر درخواست تکمیل‌شده را جدا بررسی می‌کنند، چون پاسخ تاریخچه ممکن است بلافاصله ارسال منتظر را شروع کند.

بستهٔ قطعی 0.4.2 با ۱۲ فایل ساخته شد. بررسی خواندنی تولید، نسخهٔ فعال 0.4.1 و برابر بودن هر ۱۲ فایل با Git را تأیید کرد؛ انتشار رسمی، نصب و بررسی مرورگر تولید هنوز باقی‌اند.

انتظار پیام فقط در همان document است؛ ترک/reload صفحه آن را نگه نمی‌دارد. نوشتن هنگام ارسالِ فعال یا reset همچنان قفل است. Safari/iOS/Android فیزیکی و کیبورد مجازی در این دور بررسی نشده‌اند؛ تأخیر شبکه و زمان مدل کاهش داده نشده‌اند.
