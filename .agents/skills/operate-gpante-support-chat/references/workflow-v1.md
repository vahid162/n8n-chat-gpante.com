# قرارداد نگهداری نسخهٔ اول

منبع: همین checkout. تاریخ مبنا: ۱۹ اکتبر ۲۰۲۶. این سند دستور انتشار خودکار نیست؛ مجوز درخواست فعلی مقدم است.

## ساختار واقعی

نام اصلی `gpante.com — AI Support — Main` است. Chat Trigger → اعتبارسنجی ورودی → رزرو سقف درخواست در PostgreSQL → Agent با DeepSeek و حافظه → پاک‌سازی پاسخ. ورودی نامعتبر و خطای بودجه مستقیماً پاسخ فارسی می‌گیرند. سه ابزار `Product Search`، `Product Details` و `Knowledge Search` از نوع native Workflow Tool با `source=parameter` هستند؛ هر ابزار چهار نود داخلی دارد و ورودی `query` را به‌صورت رشتهٔ JSON می‌گیرد. فعلاً سه ورک‌فلوی فرزند جدا وجود ندارد.

بدون workflowInputs schema، نود نصب‌شده از DynamicTool استفاده و رشتهٔ ورودی را به `{query: input}` تبدیل می‌کند؛ trigger داخلی passthrough آن را نگه می‌دارد. این قرارداد از منبع نصب‌شده بررسی شده، ولی tool-calling واقعی مدل هنوز آزموده نشده است. خروجی چت فقط لینک inline مجاز را نگه می‌دارد؛ تصویر به لینک تبدیل و تعریف لینک ارجاعی غیرفعال می‌شود.

مقصدها در کد ثابت‌اند: Store API فهرست محصولات، WordPress posts و pages. پارامتر URL، SQL یا کد آزاد از مدل دریافت نمی‌شود. جست‌وجو و جزئیات هر دو از فهرست محصولات با `catalog_visibility=search` استفاده می‌کنند؛ جزئیات به include شناسهٔ مثبت محدود است. فیلدهای خروجی allowlist دارند و شامل فایل/دانلود/مشتری نیستند. راهنماها فقط شناسه‌های عمومی ۴۷۵۲ و ۴۷۴۳ هستند.

انطباق ویژگی‌ها دقیق و هم‌زمان است. نام taxonomy در منبع مشترک است و slugها از کاتالوگ واقعی گرفته شده‌اند. افزودن term یا alias تازه باید با منبع فعلی مقایسه شود؛ برای جبران نبود نتیجه، شرط را خودکار حذف نکن. term ترکیبی متریال به معنی term ساده نیست. صفحهٔ پنج‌تایی، نمایهٔ محدود محصول نیست؛ `pagination` مرز پاسخ و وضعیت کامل/ناقص را نشان می‌دهد.

## منابع و بازسازی

`src/catalog.cjs` و `src/chat.cjs` import-free هستند؛ سازنده آخرین `module.exports` را حذف و همان منبع آزموده‌شده را در Code node جاسازی می‌کند. پرامپت از `src/system-message.txt` می‌آید. JSON خروجی را دستی به منبعی مستقل تبدیل نکن؛ منبع را تغییر بده و بازسازی کن.

`node scripts/build-workflow.cjs` خروجی قطعی در `workflows/gpante-support-main.json` می‌سازد. فایل عمومی شناسهٔ استقرار، اتصال Credentials یا کلید ندارد و inactive است. برای به‌روزرسانی همین استقرار، ابتدا تعریف واقعی را خصوصی دریافت و اختلاف آن را بررسی کن؛ در کپی خصوصی شناسهٔ اصلی و اتصال‌های معتبر را حفظ کن. ورود فایلِ بدون شناسه، ورک‌فلوی دیگری می‌سازد.

نام اتصال‌های مورد استفاده در استقرار فعلی: DeepSeek موجود برای مدل و اتصال مستقل دیتابیس چت برای Reserve Request Budget و Conversation Memory. شناسه/جزئیات اتصال‌ها در Git نگهداری نمی‌شوند. مدل فعلی در منبع `deepseek-flash` است؛ انتخاب اتصال، شاهد موفقیت فراخوانی مدل نیست.

در محیط فعلی Node روی میزبان در دسترس نبود؛ ساخت/آزمون با Node داخل کانتینر n8n انجام شد، بدون نصب وابستگی جدید یا restart. CLI رسمی import برای پیش‌نویس غیرفعال به restart نیاز نداشت. API key از دیتابیس استخراج نشد؛ احراز هویت API هنوز ایجاد/تأیید نشده است.

## قرارداد PostgreSQL

دیتابیس کاربردی موجود: `project_db`. نقش Login اختصاصی `gpante_chat_app` مالک schema `gpante_chat` است و هنگام ایجاد، هیچ دسترسی SELECT/INSERT/UPDATE/DELETE به جدول‌های دیگر نداشت. رمز جدید فقط در Credential رمزگذاری‌شدهٔ n8n و فایل موقت محافظت‌شده برای import استفاده شد.

- `histories(id, session_id, message, created_at)` سازگار با حافظهٔ native PostgreSQL؛ کلید نشست `gpante_chat:<sessionId>`، پنجره ۶ نوبت.
- `request_counters(counter_key, window_start, requests)` و تابع `reserve_request(text)` سقف‌ها را به‌صورت تراکنشی رزرو می‌کنند. قفل advisory کوتاه، رزرو هم‌زمان را هماهنگ می‌کند؛ در صورت مشاهدهٔ contention نیازمند اندازه‌گیری مجدد است.
- پیش‌فرض پیش‌نویس: ۱۰ درخواست نشست/۶۰ ثانیه، ۲۰۰۰ درخواست سراسری/۲۴ ساعت و پاک‌سازی تاریخچهٔ بیش از هفت روز هنگام درخواست بعدی. این رزرو تعداد درخواست است، سقف قطعی هزینهٔ مدل نیست.
- شمارندهٔ نشست تازه پس از تأیید ظرفیت جهانی ساخته می‌شود. پاسخ خطای دیتابیس اجازهٔ فراخوانی مدل نمی‌دهد.

`sql/chat.sql` migration اولیه است؛ روی schema موجود دوباره اجرا نشود. برای تغییر بعدی migration متناسب با وضعیت واقعی بنویس. بازگرداندن JSON ورک‌فلو، migration یا تاریخچه را بازنمی‌گرداند. پیش‌نویس را می‌توان غیرفعال نگه داشت و اتصال‌هایش را جدا کرد؛ حذف schema/تاریخچه به مجوز و ارزیابی دادهٔ واقعی نیاز دارد.

## اعتبارسنجی و محدودیت‌ها

آزمون‌های Node با دادهٔ مصنوعی، بررسی خواندنی ابزارهای عمومی و `tests/database.sql` با rollback اجرا می‌شوند. `scripts/validate-native.cjs` نوع نودها، کامپایل Code، activation validation و SDK strict را روی کپی خصوصی بررسی می‌کند؛ Credentials حذف‌شدهٔ فایل عمومی باعث شکست درستِ activation validation می‌شوند.

اعتبارسنجی ساختاری جای اجرای نودها نیست: در task runner این نسخه، اشیای JSON ممکن است از realm دیگری بیایند و مقایسهٔ prototype با `Object.prototype` معتبر نباشد. آزمون بازگشت مستقل وجود دارد. HTTP Request 4.4 در فیلد JSON Query رشته می‌خواهد؛ سازنده از `JSON.stringify($json.qs)` استفاده می‌کند.

CLI `execute` ممکن است خطا را در logger بنویسد؛ صرف exit code یا خروجی خالی موفقیت را ثابت نمی‌کند. برای آزمون مصنوعی، خروجی محافظت‌شده با `N8N_LOG_OUTPUT=console` و وضعیت ساختاریافتهٔ `status/resultData.error` بررسی شد. اجرای CLI مجزا از broker موقت جدا استفاده کرد؛ سرویس اصلی restart نشد. هیچ اجرای آزمایشی به woo2 متصل نیست.

پیش از انتشار: پاسخ و tool-calling واقعی DeepSeek، حافظهٔ چندنوبتی/هم‌زمان، حذف محصول پنهان و رمزدار، ویجت و RTL، پراکسی و هویت/IP، سیاست نگهداری و حذف مستقل از ترافیک، اهداف ظرفیت/تاخیر و هزینه، و مسیر بازگشت باید بررسی شوند. شناسهٔ نشستِ ارسالی مرورگر احراز هویت نیست. CORS به‌تنهایی کنترل سوءاستفاده نیست. اجرای موفق ابزارها، کیفیت پاسخ فارسی مدل یا آمادگی تولید را ثابت نمی‌کند.
