# ارزیابی کیفیت پاسخ

`evals/answer-quality.json` شامل ۶۵ سناریوی مصنوعی فارسی است: FAQ و خرید، مشکل فایل، طراحی، محصول با شروط هم‌زمان، دسته و ترتیب، مقاله، مقررات، ادامهٔ گفتگو، سؤال ترکیبی، اطلاعات ناموجود و خطای منبع. هیچ transcript مشتری یا دادهٔ خصوصی در مجموعه نیست.

این مجموعه سه چیز را جدا می‌سنجد:

- **مسیر:** ابزار و منبع مورد انتظار انتخاب شده و شروط صریح حفظ شده‌اند؟
- **بازیابی:** برای ۱۵ عبارت مشخص، پاسخ مرتبط در صفحهٔ اول FAQ برمی‌گردد؟
- **پاسخ:** مرجع از نتیجهٔ همان نوبت آمده، قیمت/واحد با نتیجه سازگار و عبارت‌های ممنوع حذف شده‌اند؟

فیلد `reference` معیار بازبینی انسانی هر مورد است. فیلدهای `mustIncludeAny` و `mustNotInclude` فقط عبارت‌های مشخص را بررسی می‌کنند؛ بازنویسی هم‌معنی ممکن است به بازبینی انسانی نیاز داشته باشد. امتیاز عبور از این کنترل‌ها، درصد صحت معنایی همهٔ پاسخ‌ها نیست. سازگاری فنی، ارتباط پیشنهاد، ادعاهای علت‌ومعلولی و حفظ معنای کامل FAQ باید جدا با منبع مقایسه شوند.

## اجرا بدون شبکه

اجرای پیش‌فرض فقط ساختار مجموعه را بررسی می‌کند؛ نه مدل فراخوانی می‌شود و نه سایت خوانده می‌شود:

```sh
python3 scripts/evaluate-answer-quality.py
python3 -m unittest discover -s tests -p test_answer_quality.py
```

خروجی `generationEvaluated=false` یعنی پاسخ مدل در آن اجرا ارزیابی نشده است. تعداد ۶۵، اندازهٔ مجموعهٔ آزمون است و محدودیتی برای کاتالوگ یا منابع محصول نیست.

## بررسی بازیابی FAQ

با این گزینه، فقط GET عمومی FAQ اجرا می‌شود؛ تماس مدل، کلید، نشست یا پیام کاربر ساخته نمی‌شود:

```sh
python3 scripts/evaluate-answer-quality.py --retrieve
```

مقصد مجاز دقیقاً `https://gpante.com/wp-json/gpante-support/v1/knowledge` است؛ redirect، URL دلخواه و هدر اعتبارنامه پشتیبانی نمی‌شوند. مهلت هر خواندن ۱۲ ثانیه و پاسخ حداکثر ۱ MiB است. این سنجش مستقل، حضور پاسخ مورد انتظار در **صفحهٔ اولِ ابزار** را بررسی می‌کند. `miss` با خطای خواندن `source_error` جدا گزارش می‌شود. این آزمایش زمان یا کیفیت کامل پاسخ دستیار را اندازه نمی‌گیرد.

برای بازپخش بدون شبکه، فایل JSON با نگاشت عبارت جست‌وجو به آرایهٔ نتایج عمومی همان API تهیه کنید:

```json
{
  "ایمیل": [
    {"id": "faq-example", "title": {"rendered": "اگر ایمیل ندارم، می‌توانم خرید کنم؟"}}
  ]
}
```

```sh
python3 scripts/evaluate-answer-quality.py --retrieval-fixture /tmp/faq-results.json
```

برای اجرای کامل fixture باید همهٔ عبارت‌های `retrieval.query` حاضر باشند؛ مورد غایب خطای منبع است. تغییر واقعی متن/عنوان FAQ ممکن است نیازمند بازبینی انتظارهای مجموعه باشد؛ انتظارها بدون بررسی منبع برای سبزشدن آزمون تغییر نکنند.

## بررسی پاسخ‌های ثبت‌شدهٔ مصنوعی

اجرای نمونه‌های مدل جدا از این ابزار و فقط با اختیار و بودجهٔ مناسب انجام می‌شود. این اسکریپت خودش مدل یا ورک‌فلو را اجرا نمی‌کند. نمونه‌ها را در فایل خصوصی خارج از Git نگه دارید و فقط موردهای مصنوعی این مجموعه را وارد کنید. قرارداد فایل، یک آرایه از رکوردهاست:

```json
[
  {
    "id": "faq-email",
    "answer": "در مسیر معمول خرید، ایمیل اختیاری است. [مرجع](https://gpante.com/faq-ai/#faq-example)",
    "modelCalls": 2,
    "toolCalls": [
      {
        "name": "Knowledge_Search",
        "arguments": {"source": "faq", "search": "ایمیل"},
        "result": {
          "ok": true,
          "source": "faq",
          "results": [{"id": "faq-example", "url": "https://gpante.com/faq-ai/#faq-example"}]
        }
      }
    ]
  }
]
```

شناسهٔ `faq-example` صرفاً نمونهٔ شکل داده است؛ نمونهٔ واقعی باید لینک و نتیجهٔ همان نوبت را داشته باشد. برای محصول، از شکل نرمال‌شدهٔ ابزار استفاده کنید؛ مثل `price: {amount: "1250", currency: "IRT"}`. تغییر قیمت یا واحد بدون تغییر شاهد رد می‌شود؛ قیمت صفر معتبر است و تبدیل خودکار ریال/تومان انجام نمی‌شود. این کنترل وجود مقدار و واحد در نتایج همان نوبت را می‌سنجد؛ نسبت‌دادن قیمتِ یک محصول به محصول دیگر همچنان به بازبینی انسانی نیاز دارد.

```sh
python3 scripts/evaluate-answer-quality.py --samples /tmp/synthetic-chat-samples.json
```

نمونهٔ غایب شکست محسوب می‌شود؛ شناسهٔ تکراری یا نامعلوم خطاست. تعداد تماس مدل اگر ثبت نشده باشد «مشاهده‌نشده» باقی می‌ماند و از روی پاسخ حدس زده نمی‌شود. خروجی فقط شناسهٔ مورد، کد شکست و شمارها را دارد و متن پاسخ را چاپ نمی‌کند. کد خروج ۰ یعنی همهٔ کنترل‌های اجراشده گذشتند، ۱ یعنی حداقل یک مورد شکست خورد و ۲ یعنی ورودی/اجرای ابزار نامعتبر بود.

برای مقایسهٔ نسخه‌ها، مجموعه و قرارداد ورودی ثابت را روی نسخهٔ پیشین و نامزد اجرا کنید؛ نتیجهٔ بازیابی، نتیجهٔ پاسخ و بازبینی انسانی را جدا ثبت کنید. تغییر مجموعه یا منبع را همراه نسخه/تاریخ ثبت کنید تا اختلاف امتیاز به‌اشتباه به مدل یا کد نسبت داده نشود.

## منابع سایت و خواندن محتوا

۱۵ سناریوی جدید برای برگه، دوره، گزینهٔ رایگان، نصب نسخهٔ مشخص، برگهٔ تازه، تغییر محتوا، منبع خصوصی، ناوبری حساب، سؤال ترکیبی و شکست منبع اضافه شده است. `Knowledge_Search source=site` منبع مشترک و `Knowledge_Read` خواندن محدود صفحه/نوشته است؛ منبع Read همیشه site است و از آرگومان مدل گرفته نمی‌شود. نتیجهٔ خواندن باید به ID همان درخواست تعلق داشته باشد.

کنترل پیش‌فرض همچنان فقط قرارداد ۶۵ سناریو را می‌سنجد؛ به معنی اجرای ۶۵ پاسخ مدل نیست. بازیابی ۱۵ FAQ مستقل باقی مانده است. آزمون WordPress بومی و نمونه‌های واقعی برگه/دوره در `specs/016-site-knowledge/verification.md` جدا ثبت می‌شوند.
