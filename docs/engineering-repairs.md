# اصلاح‌های مهندسی پس از ممیزی

در۲۴اکتبر۲۰۲۶، افزونهٔ رسمی **[0.10.2](https://github.com/vahid162/n8n-chat-gpante.com/releases/tag/wordpress-v0.10.2)** نصب و Main **1.7.1** منتشر شد. migration006 یک‌بار با Main متوقف و تخلیه‌شده اجرا شد؛ متن/زمان تاریخچه، دفتر مالی و بودجه/سیاست قبل و بعد برابر ماندند و backfill شناسه‌ها مورد مفقود نداشت. هر۱۶ فایل نصب‌شده و SHA256 با Release و منبع برابرند. چهار سؤال مصنوعی روی سرویس واقعی و بازخوانی نهایی نیز موفق‌اند؛ دامنه و حدود این شواهد در ادامه آمده است. مدل، بودجه۲دلار، سقف چهار تماس/سه ابزار/دو درخواست هم‌زمان، پوشش خودکار تمام محتوای عمومی مجاز، API و گزینه‌های مدیر حفظ‌اند.

همچنین backend مصنوعی، replay، شناسهٔ پایدار، صفحه‌بندی، feedback متعلق به نشست، انقضای ثابت و تغییر سیاست را بازسازی می‌کند. افزایش مدت، نوبت زنده را از زمان اصلی تمدید می‌کند؛ پیام منقضی یا مخفی دوباره زنده نمی‌شود. HTTP خارجیِ پیش‌بینی‌نشده در محیط بومی مسدود است.

## بررسی محلی و ایزوله

- **۱۶۳ تست JavaScript**، **۲۹ تست Python** و **هشت مجموعه PHP**؛ PHP lint و WordPress coding standards موفق‌اند.
- **۲۶۹ assertion بومی** روی WordPress7.1.3/WooCommerce11.2.1/MariaDB11.4؛ پوشش SQL واقعی دسته/رتبه‌بندی، واجدشرایط‌بودن، FAQ، متن سایت، چرخه و lease نمایه، تنظیمات/uninstall و backend مصنوعی.
- PostgreSQL17 دورریختنی: migrationهای اولیه تا006، آرشیو، مالی، گفتگو، گزارش و محافظ retry موفق‌اند. fixture پیش از003 حفظ دقیق شناسه/متن/زمان و ledger را می‌سنجد؛ upgrade جداگانهٔ پیش از006، backfill و replay درخواست موجود را تأیید کرد.
- هم‌زمانی واقعی PostgreSQL: از دو رزرو فقط یکی با ظرفیت باقی‌مانده پذیرفته شد؛ ماه UTC، تسویهٔ یک‌باره و یک turn برای دو ارسال هم‌شناسه حفظ شدند؛ تماس مدل صفر.
- گراف Main69، Admin5 و Retention2 در کانتینر n8n بدون شبکه با ارجاع‌های اعتبار مصنوعی، activation و SDK strict و کامپایل Code را با صفر warning گذراندند. قالب عمومی عمداً credential واقعی ندارد؛ اعتبارسنجی اولیهٔ بدون این ارجاع‌ها، همان credential مفقود را رد کرد.
- Chromium در وردپرس HTTPS ایزوله: ارسال، لینک، reload، حفظ draft پس از خطا، history پیش از retry، clear، صفحه‌کلید و سه اندازه موفق؛ خطای runtime صفر. سه مجموعه HTTP مدیریت، nonce/capability، پنهان‌بودن کلید و حفظ تنظیمات را گذراندند.
- Chromium156 و Firefox157 در مرورگر واقعی با تمام درخواست‌های intercept‌شده: تاریخچه و حفظ صفحهٔ قدیمی پس از refresh، replay همانsendId، بازخورد، fallback، clear و چهار اندازه موفق‌اند؛ مدل و ترافیک تولید صفر و خطای runtime صفر.
- actionlint و برابری خروجی‌های تولیدی موفق‌اند. بستهٔ۱۶فایلی0.10.1 با SHA256 `c076ad71c8ff394c3c8c1a46b1bfa7925e9c0480b0c724464756eaef0baba718` ساخته شد.

تست‌های خطای جدید پیش از اصلاح شکست خوردند؛ شکاف‌های کشف‌شده در بازبینی مستقل نیز به regression تبدیل شدند. [فرمان‌ها و محیط](testing.md) و [قرارداد نگهداری شناسه](conversation-archive.md) مرجع ادامه‌اند.

## ارتقا و حدود

بررسی تکمیلیِ حداقل نسخه، شکست واقعی جست‌وجوی محصول در WordPress6.6/PHP8.1.34/WooCommerce9.1.4 را آشکار کرد: Store API قدیمی فیلد `is_password_protected` ندارد. افزونه0.10.2 نبود این فیلد را فقط پس از بررسی مستقلِ نوشتهٔ منتشرشده، رمز و نمایش محصول می‌پذیرد؛ مقدار صریح true/null/رشته/عدد همچنان رد می‌شود. regression در مجموعهٔ PHP کاتالوگ پیش از اصلاح شکست خورد و پس از آن شش مجموعه بومی با۲۷۳ assertion روی همین ترکیب حداقل موفق شدند. بستهٔ۱۶فایلی0.10.2 با SHA256 `c0b3de5998cd2358690b0b0f8ac73546e75a301a032d777493edf50bf17338eb` از Release رسمی نصب و با منبع تطبیق داده شد؛ بستهٔ منتشرشده0.10.1 تغییر نکرد.

تست شبکهٔ دو‌سایته، جدایی تنظیمات و نمایه را تأیید کرد و باقی‌ماندن دادهٔ سایت دوم پس از uninstall را آشکار ساخت. پاک‌سازی اکنون فقط داده و cron متعلق به همین افزونه را با صفحه‌های۱۰۰سایتی پاک و context اولیه را بازیابی می‌کند؛ regression پیش از اصلاح شکست خورد و پس از آن همراه۲۵ assertion شبکه موفق شد. نمونهٔ گرمِ جست‌وجوی عمومی روی۱۲۰۰سند مصنوعی با۲۰۰خواندن پیاپی، میانه۵٫۷۰۵میلی‌ثانیه و صدک۹۵ برابر۷٫۶۹۶میلی‌ثانیه داشت؛ هر خواندن۴query. این اندازه‌گیری bootstrap وردپرس، HTTP، هم‌زمانی، n8n و مدل را شامل نمی‌شود و تضمین ظرفیت تولید نیست.

006 یک migration افزایشیِ یک‌باره پس از005 است و Main باید تخلیه باشد. `admit_v4` همان۹آرگومان را دارد و cleanup قبلی با حفظ ledger بازاستفاده می‌شود. جدولsend_guards فقط شناسهٔ HMAC نشست، sendId و انقضا دارد؛ عمرش۳۰روز بی‌فعالیتی backend به‌اضافه۵دقیقه حاشیهٔ پاسخ است. متن گفتگو همچنان حداکثر۳۰روز است. شناسهٔ کاملاً حذف‌شده پیش از006 و تلاش پس از ناوبری قابل بازسازی نیستند.

پیش از استقرار، گراف‌های فعال/پیش‌نویس Main/Admin/Retention و هر۱۶ فایل افزونه با منبع نصب قبلی برابر بودند؛ نمایه۱٬۱۴۵ سند مجاز داشت، با شمار مستقل برابر بود و سند نامعتبر نداشت. نسخهٔ جدید با حفظ کل تنظیمات، اتصال‌ها، مدل و سقف‌ها نصب/منتشر شد؛ GitHub CI و اعتبارسنجی n8n نصب‌شده موفق‌اند. [تعرفه و مدل رسمی](https://api-docs.deepseek.com/quick_start/pricing/) در۲۴اکتبر دوباره بررسی شدند و تغییر نکردند؛ اعتبار نرخ قبلی تمدید نشد. لاگ یا متن مشتری برای این بررسی کپی نشد. چهار سؤال مصنوعی در Firefox روی سرویس واقعی دربارهٔ آموزش کورل، مقاله، محصول MDF/DXF/۲٫۷ و FAQ خرید، لینک منبع و بازیابی برابر پس از reload داشتند. همان sendId یک turn را بدون تماس مدل تازه بازپخش کرد، بازخورد مفید ذخیره شد و clear خاموش/رد مستقیم403 بدون حذف تاریخچه تأیید شد. هر چهار turn از مسیر مدیریت معتبر synthetic برچسب خوردند؛۸ تماس با usage کامل، هزینهٔ حساب‌شدهٔ۰٫۰۲۱۸۵۰۵ دلار و زمان۶٫۸ تا۱۰٫۱ثانیه ثبت شد.

بازخوانی نهایی، نسخهٔ فعال و پیش‌نویس Main/Admin/Retention را با منبع برابر، دو گراف همراه و۲۲ workflow نامرتبط را ثابت و تنظیمات/اتصال‌ها/سیاست را محفوظ یافت. نمایه با شمار مستقل۱٬۱۴۵ سند عمومی مجاز برابر، کامل و بدون مورد نامعتبر بود؛ محافظ شناسهٔ مفقود و lease فعال صفر بودند. این بررسی حفظ تاریخچه و دفتر مالی هنگام migration را از مقایسهٔ قبل/بعد تأیید می‌کند؛ پس از آن، تماس‌های مصنوعی هزینهٔ معتبر خود را به دفتر افزودند. رفتار زیر بار، تمام ترکیب‌های نسخه و Safari/iOS روی دستگاه واقعی بررسی نشده‌اند؛ قبولی ارزیاب یا این چهار نمونه، درصد دقت معنایی دستیار نیست.

پس از ارتقا، اجرای صریحِ نسخهٔ منتشرشدهٔ Retention نیز موفق شد و شمار حذف متن/گزارش/محافظ منقضی را صفر برگرداند؛ فیلد `expiredSendGuardsRemoved` اجرای wrapper جدید را تأیید کرد. بودجه و سیاست پس از آن ثابت و lease فعال صفر بود. این اجرا به‌صورت صریح فراخوانی شد؛ چهار اجرای ساعتی طبیعیِ موفقِ پیش از ارتقا جداگانه مشاهده شدند.
