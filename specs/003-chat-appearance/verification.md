# شواهد ظاهر — ۲۰ اکتبر ۲۰۲۶

| بررسی | نتیجه |
| --- | --- |
| PHP presentation | ایجاد غیرautoload و idempotent، حفظ schema آینده، text/color allowlist، آستانهٔ دقیق contrast، رد ورودی بد، رد غیرمدیر، reset مستقل و خروجی عمومی مجاز موفق |
| کنترلر JavaScript | خواندن بدون cache، شکست/پاسخ نامعتبر، متن بدون HTML، policy واقعی و نبود درخواست تکراری بررسی شدند؛ اجرای کند دریافت ظاهر هم چت را مسدود نمی‌کند |
| WordPress واقعی محلی | فرم native، nonce درست/غلط، مدیر/مشترک، escape واقعی، contrast/طول/CSS نامعتبر، بازنشانی و hash ثابت کل تنظیمات اتصال موفق |
| Chrome محلی | ذخیره از صفحهٔ ظاهر، نمایش رنگ/عنوان/دکمه/خوشامد/placeholder تازه روی HTML قدیمی کش‌شده، policy درست، سه اندازهٔ 1440×1000، 390×844 و 844×390 با کنترل‌های قابل دسترس و بدون خطای runtime موفق |
| رگرسیون مرورگر | ارسال مصنوعی، لینک امن، بازیابی پس از reload، حفظ draft و retry پس از خطا، تأیید clear و Escape در WordPress واقعی موفق |
| بسته | ۱۲ فایل runtime؛ نسخهٔ هدر، constant و Stable tag یکسان؛ ساخت قطعی و پنج تست بسته/انتشار موفق |

۴۸ آزمون Node، مجموعه‌های PHP settings/appearance/bridge/catalog، WPCS و پنج تست Python بسته/انتشار موفق بودند. بررسی scoped axe پس از اصلاح landmark سربرگ و focus ناحیهٔ اطلاع‌رسانی، هیچ violation ثبت نکرد.

تمام پیام‌ها و داده‌های این دور آزمون محلی مصنوعی‌اند؛ هیچ تماس مدل برای ظاهر لازم نبود. CI بررسی افزونه و دیتابیس مجزای آزمون موفق بود. PR قابلیت merge و Release رسمی 0.3.0 منتشر شد؛ tag به commit مورد انتظار اشاره داشت و ZIP دانلودشده، checksum و هر ۱۲ فایل با منبع برابر بودند.

ارتقای تولید پس از پشتیبان خصوصی افزونه و تنظیمات، با WP-CLI/PHP 8.3 و کاربر مالک سایت انجام شد. hash کل runtime، سیاست مرکزی، فهرست افزونه‌های فعال و قالب قبل/بعد برابر ماند. گزینهٔ ظاهر غیرautoload و مقدار اولیه پیش‌فرض است؛ هیچ رنگ/متن مصنوعی روی تولید ذخیره نشد. صفحهٔ واقعی مدیر شامل عنوان، nonce و هشت ورودی رنگ بدون افشای کلید render شد. فقط کش صفحات همین سایت تازه شد؛ مسیر عمومی appearance با no-store و asset نسخهٔ 0.3.0 خوانده شدند.

Chrome واقعی با TLS معتبر روی قالب سایت، دریافت ظاهر تازه، یک widget، تاریخچه و کنترل‌های قابل دسترس در همان سه اندازه را با صفر خطای runtime تأیید کرد. این بررسی تولید بدون ارسال پیام و تماس مدل بود؛ ثبت و ارسال پرسش مصنوعی در محیط محلی بررسی شد. هیچ SQL یا workflow برای این قابلیت تغییر نکرده است.

Safari/iOS واقعی، multisite، همهٔ نسخه‌های حداقل و بار گسترده بررسی نشده‌اند. ظاهر در بارگذاری بعدی تازه می‌شود؛ تب از قبل باز نیاز به reload دارد. هنگام اولین ارتقا، کش HTML/asset همین سایت باید تازه شود.
