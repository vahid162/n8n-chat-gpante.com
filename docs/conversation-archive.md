# آرشیو گفتگو و تنظیم تاریخچه

از نسخهٔ 0.2.0، در پیشخوان وردپرس وارد **چت پانته ← گفتگوها** شوید. فقط مدیر دارای `manage_options` به این صفحه دسترسی دارد؛ نشست‌ها ناشناس‌اند و با حساب مشتری یکی نیستند.

در «سیاست تاریخچه و پاک‌کردن کاربر»، مدت نمایش را برای همهٔ کاربران **۳، ۷، ۱۵ یا ۳۰ روز** تعیین کنید. «کاربر بتواند تاریخچهٔ قابل مشاهدهٔ خود را پاک کند» دکمه و مجوز سروری آن را با هم کنترل می‌کند. پیش‌فرض ۳۰ روز و پاک‌کردن روشن است. آرشیو مدیر همیشه ۳۰ روز است؛ یک ماه یعنی ۳۰ روز.

| رویداد | تاریخچه و زمینهٔ مدل | آرشیو مدیر |
| --- | --- | --- |
| پایان مدت انتخاب‌شده | دسترسی بسته می‌شود | تا ۳۰ روز از پرسش باقی است |
| پاک‌کردن کاربر | پیام‌های قبلی بسته؛ گفتگو از نو | باقی است |
| افزایش مدت | پیام منقضی یا پاک‌شده برنمی‌گردد | عمرش تمدید نمی‌شود |
| خاموش‌کردن دکمه | درخواست مستقیم پاک‌کردن هم رد می‌شود؛ انقضای خودکار برقرار است | بدون تغییر |
| پایان ۳۰ روز | دسترسی بسته | دسترسی بسته؛ حذف فیزیکی تا نوبت ساعتی بعد |

تغییر مدت روی پیام‌های هنوز قابل مشاهده اعمال می‌شود؛ زمان اصلی پرسش تغییر نمی‌کند. سیاست در بازشدن پنجره، بازگشت focus و هر دقیقهٔ پنجرهٔ باز دوباره خوانده می‌شود. deadline شناخته‌شده با timer محلی هم اعمال می‌شود. سرور در همهٔ خواندن‌ها و درخواست‌ها سیاست جاری را اعمال می‌کند.

فهرست گفتگوها صفحه‌بندی، فیلتر تاریخ UTC، وضعیت و دسترسی کاربر و جست‌وجوی محدود متن دارد. با بازکردن نشست، تمام رکوردهای باقی‌مانده با صفحه‌های ۲۰تایی قابل مرورند؛ محدودیت شش نوبت زمینهٔ مدل، محدودیت آرشیو مدیر نیست. متن‌ها به‌شکل امن و بدون اجرای HTML نمایش داده می‌شوند.

پرسش پذیرفته‌شده پیش از تماس مدل ثبت می‌شود. پاسخ موفق یا کد خطا بعد از پایان ثبت می‌شود. اجرای قطع‌شده، پاسخ یا مدت ساختگی ندارد. هزینهٔ نمایش‌داده‌شده محافظه‌کارانه است؛ در نبود usage کامل ممکن است رزرو کامل باشد. «—» یعنی داده ثبت نشده است، نه صفر. رکوردهای مهاجرتی `legacy` زمان اصلی دارند و جفت/اطلاعات فنی نامعلوم برایشان ساخته نشده است. پیام قبلاً حذف‌شده قابل بازیابی نیست. خرابی قبل از دریافت سرویس، گفتگو ثبت‌شده محسوب نمی‌شود.

از Main 1.2.2، برای خطاهای تازه در جزئیات گفتگو، کد مشخص فنی دیده می‌شود. این کدها مقادیر ثابت برنامه‌اند؛ متن پاسخ خام مدل، آرگومان ابزار، هدر و کلید در گزارش فنی ذخیره نمی‌شوند. پرسش/پاسخ معمول همچنان فقط تابع سیاست قبلی آرشیو است.

| کد | معنی |
| --- | --- |
| `model_tool_invalid_id` / `model_tool_duplicate_id` | شناسهٔ نامعتبر یا تکراری در همان batch |
| `model_tool_invalid_type` / `model_tool_unknown_name` / `model_tool_invalid_arguments` | ساختار، نام یا قالب آرگومان ابزار پذیرفته نشده |
| `model_tool_calls_missing` / `model_tool_limit` | فهرست ابزار خالی/ناقص یا عبور از ظرفیت باقی‌ماندهٔ سه ابزار |
| `model_finish_length` / `model_content_filter` | توقف به سقف خروجی یا فیلتر ارائه‌دهنده |
| `model_provider_resource` / `model_provider_aborted` | توقف اعلام‌شدهٔ سرویس مدل |
| `model_finish_mismatch` / `model_finish_unexpected` / `model_empty_content` | ناسازگاری علت پایان، علت ناشناخته یا محتوای خالی |
| `model_http_error` / `model_message_missing` / `model_usage_invalid` | شکست HTTP، پیام مفقود یا آمار مصرف نامعتبر |

خطاهای قدیمی `invalid_model_response` به‌صورت تاریخی حفظ می‌شوند؛ نبود پاسخ خام اجازهٔ تعیین جزئیات گذشته را نمی‌دهد. این ارتقا به نصب افزونه یا migration تازه نیاز ندارد و پیام عمومی مرورگر همچنان محدود و بدون جزئیات داخلی است.

## نگهداری و ارتقا

- WordPress فقط رابط مدیریت است؛ پیام‌ها در `project_db.gpante_chat` می‌مانند و در وردپرس کپی نمی‌شوند. مرور آرشیو هیچ تماس مدل ندارد و با چت خاموش یا بودجهٔ تمام‌شده کار می‌کند.
- کلید مدیریت از کلید عمومی مستقل است؛ فقط سرور وردپرس آن را به مسیر مدیریت می‌فرستد. تنظیم آن در «تنظیمات اتصال» است؛ کلید خالی مقدار قبلی را حفظ می‌کند و مقدار ذخیره‌شده نمایش داده نمی‌شود.
- ابتدا migrationهای قبلی و سپس `sql/003-conversation-archive.sql` یک‌بار روی دیتابیس پروژه اجرا شوند. پیش از 003، Main متوقف و درخواست‌های درحال اجرا تخلیه شوند؛ migration با lease فعال رد می‌شود. در همان transaction یا بلافاصله پس از آن، نقش مدیریت فقط USAGE همان schema و EXECUTE تابع `admin_api(jsonb)` بگیرد؛ دسترسی مستقیم جدول نگیرد.
- Main1.7.0 پس از migrationهای004/005 از `admit_v4` و `finish_v4` استفاده می‌کند؛ v3 برای قرارداد قبلی و زمینهٔ کوتاه مدل حفظ می‌شود. workflow خصوصی `gpante.com — AI Support — Admin` از نقش/کلید مستقل استفاده می‌کند. اجرای خام Main و Admin خاموش می‌ماند؛ Retention فقط زمان و شمار پاک‌سازی را ثبت می‌کند.
- بعد از backend، ZIP افزونه ارتقا داده شود. نام option حفظ شده، schema به ۲ ارتقا می‌یابد و کلید قبلی/فعال‌بودن حفظ می‌شوند. کلاینت قدیمی حق ارسال یا پاک‌کردن با متن قدیمی ندارد؛ باید صفحه را تازه کند. کش همان سایت پاک شود.
- برگشت کورکورانه به SQL قدیمی مجاز نیست: reset قدیمی آرشیو را حذف می‌کرد. در rollback، schema و نگهداری ۳۰روزه را حفظ و در صورت ناسازگاری فقط چت را موقتاً خاموش کنید. deactivation/uninstall افزونه به آرشیو یا دفتر مالی دست نمی‌زند.
- پاک‌سازی گفتگو دفتر مالی بدون متن را حذف یا refund نمی‌کند. فایل پشتیبانِ دارای transcript نیز باید حداکثر در ۳۰ روز منقضی شود؛ این قابلیت مجوز ساخت پشتیبان دائمی نیست. snapshot عمومی workflow، پشتیبان دیتابیس نیست. پشتیبان‌های فاقد متن، مانند فایل runtime یا schema-only، مستقل‌اند. سیاست پشتیبان سرویس خارجی خارج از کنترل این افزونه است و باید جدا بررسی شود.

## قرارداد بازیابی017

شناسهٔ تصادفی sendId به متن دقیق و نشست امضاشده وابسته است. تلاش مجددِ پاسخ موفق و هنوز قابل مشاهده، همان پاسخ را بدون رزرو/مدل برمی‌گرداند؛ درخواست ناموفق یا منقضی خودکار درخواست پولی تازه نمی‌سازد. نبود sendId رفتار قدیمی را حفظ می‌کند. تاریخچهٔ کاربر با شش نوبت کامل در هر صفحه خوانده می‌شود؛ historyResetAt پس از پاک‌کردن از تب دیگر، cache پیام‌های قدیمی را باطل می‌کند. مدت فعلی و انقضا همچنان اعمال می‌شوند. بازخورد فقط برای پاسخ موفقِ قابل مشاهدهٔ همان نشست است. گزارش فنیِ بدون کپی گفتگو حداکثر۷روز/۲۰۰۰ رکورد دارد؛ برچسب آزمون تنها از مدیریت خصوصی تغییر می‌کند.
