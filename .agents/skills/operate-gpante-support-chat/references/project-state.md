# وضعیت نگهداری پروژه

به‌روز شده در ۲۰ اکتبر ۲۰۲۶. این سند خلاصهٔ عمومی ادامهٔ کار است؛ وضعیت زنده باید دوباره خوانده شود. شناسه‌های استقرار، نسخه‌های فعال، پشتیبان‌ها، دفتر هزینه و رسیدهای عملیاتی خصوصی‌اند و وارد این مخزن نمی‌شوند.

## نسخه و منبع

| جزء | مرجع جاری |
| --- | --- |
| افزونهٔ نصب‌شدهٔ WordPress | **0.4.0**؛ [انتشار رسمی](https://github.com/vahid162/n8n-chat-gpante.com/releases/tag/wordpress-v0.4.0) |
| قرارداد افزونه | `wordpress-plugin/gpante-support-chat/`؛ schema اتصال ۲، schema مستقل ظاهر ۲، REST v1 و policy contract ۲ |
| منابع workflow | نسخهٔ 1.2.0؛ `src/` و خروجی قطعی `scripts/build-workflow.cjs` |
| مهارت canonical | همین پوشه؛ **0.7.1**؛ نسخهٔ مهارت از افزونه و workflow مستقل است |
| راهنما | [آرشیو و ارتقا](../../../../docs/conversation-archive.md)، [گزارش تولید](../../../../docs/production-readiness.md) |

کاربر راه‌اندازی و ارتقای همین چت در تولید را مجاز کرده است؛ دستور قدیمی «سایت تغییر نکند» مربوط به ساخت محلی بود. اختیار به قالب، افزونه‌ها یا سامانه‌های نامرتبط گسترش ندارد. دسترسی سرور مستقیم SSH با PHP 8.3 و WP-CLI است؛ از SentinelX استفاده نشود.

## وضعیت تأییدشده

- Main، Admin و Retention منتشر و فعال‌اند. گراف و پارامترهایشان با منابع تطبیق داده شدند. ورک‌فلوهای نامرتبط دست‌نخورده‌اند.
- migration 003 پس از توقف کوتاه Main و تخلیهٔ درخواست‌ها اجرا شد. پیام‌های قبلی، زمان اصلی و دفتر مالی حفظ شدند؛ schema کاربردی فقط در project_db است، نه دیتابیس داخلی n8n.
- پرسش پذیرفته‌شده پیش از تماس مدل ثبت می‌شود؛ پاسخ نهایی، خطا یا وضعیت قطع‌شده برای بررسی مدیر باقی می‌ماند. دادهٔ فنی قدیمی نامعلوم ساخته نشده است. آرشیو مدیر ۳۰ روز از زمان اصلی پرسش است.
- مدیر یک مدت سراسری ۳، ۷، ۱۵ یا ۳۰روزه برای کاربر تعیین می‌کند. پیش‌فرض نصب تازه ۳۰ روز و پاک‌کردن روشن است؛ سیاست جاری را از سرویس بخوانید و انتخاب مدیر را در ارتقا حفظ کنید. پاک‌کردن کاربر فقط دسترسی/زمینهٔ مدل را می‌بندد؛ آرشیو را حذف نمی‌کند. افزایش مدت، متن منقضی یا پاک‌شده را بازنمی‌گرداند.
- «چت پانته ← گفتگوها» فهرست صفحه‌بندی‌شده، جست‌وجو/فیلتر و جزئیات دارد. اتصال مدیریت کلید و نقش مستقل دارد؛ نقش SQL فقط تابع ثابت مدیریت را اجرا می‌کند. اجرای خام Main و Admin خاموش است و پیام در WordPress کپی نمی‌شود.
- ZIP رسمی 0.4.0، checksum و ۱۲ فایل نصب‌شده تطبیق داده شدند؛ schema=2، کلید قبلی و enabled حفظ شدند. کش فقط همین سایت پاک شد. کلید مدیریت خصوصی تنظیم و صفحهٔ واقعی مدیر بدون نمایش کلید render شد.
- مرورگر واقعی تولید: پاسخ واقعی، جداسازی دو بازدیدکننده، دکمهٔ خاموش و رد درخواست مستقیم clear، بازیابی پس از reload و حفظ سؤال/پاسخ در آرشیو پس از پاک‌کردن موفق بودند. سه اندازهٔ دسکتاپ/موبایل و صفر خطای runtime ثبت شدند.
- آزمون صریح نگهداری، fixture منقضی را حذف و آرشیو جدید را حفظ کرد؛ دفتر مالی تغییر نکرد. اجرای دستی به‌دلیل saveManualExecutions=false در history باقی نماند؛ نتیجه از دیتابیس تأیید شد. اجرای طبیعی ساعتی پس از استقرار نیز موفق مشاهده شد.
- ۵۵ آزمون Node، تست‌های SQL در محیط جدا و CI، PHP settings/bridge/catalog، lint/WPCS، پنج تست بسته/انتشار و WordPress/Chrome واقعی محلی موفق بودند. [شواهد تفکیک‌شده](../../../../specs/002-conversation-archive/verification.md).

نسخهٔ 0.4.0 از Release رسمی نصب شد؛ هر ۱۲ فایل با بسته و منبع برابرند. کل تنظیمات اتصال، هر دو کلید، enabled، سیاست گفتگو، فهرست افزونه‌های فعال و قالب قبلی حفظ شدند. متن‌ها و رنگ‌هایی که مدیر در نسخهٔ قبلی تنظیم کرده بود حفظ شدند؛ چهار لینک خالی به schema ظاهر اضافه شد. متن، رنگ یا لینک آزمایشی روی تولید ذخیره نشد.

اصلاح کاتالوگ stdClass نسخهٔ 0.1.1 حفظ شده است. بررسی کامل کاتالوگ و قیمت در مرحلهٔ قبلی ثبت شد؛ این ارتقا قرارداد کاتالوگ، مدل و محدودیت‌ها را تغییر نداد.

## ادامهٔ نگهداری

1. Git، نسخهٔ نصب‌شده، سیاست معتبر، نسخهٔ فعال سه workflow و اجراهای Retention را تازه بخوانید. 003 فقط یک‌بار اجرا می‌شود؛ restore نباید منطق قدیمی حذف فیزیکی را بازگرداند.
2. پشتیبان‌ها و رسیدهای خصوصی خارج از checkout عمومی‌اند. پشتیبان دارای transcript نباید آرشیو دائمی بسازد؛ سیاست سرویس پشتیبان خارجی باید جدا بررسی شود.
3. بودجهٔ تأییدشده ۲ دلار/ماه تقویمی UTC و محدودیت‌های قبلی حفظ شده‌اند. پیش از انقضای تعرفه، نرخ/context واقعی دوباره بررسی شوند؛ صرفاً تاریخ تمدید نشود.
4. سفارش، دانلود خریداری‌شده و ارجاع انسانی هنوز ساخته نشده‌اند؛ به نیاز و احراز هویت/مالکیت جداگانه نیاز دارند.

Safari/iOS واقعی، multisite، همهٔ نسخه‌های حداقل و بار گسترده بررسی نشده‌اند. ارسال دوباره پس از گم‌شدن پاسخ شبکه ممکن است request/هزینهٔ تازه بسازد؛ idempotency منطقی ارسال هنوز اضافه نشده است. حذف فیزیکی تا یک نوبت ساعتی تأخیر دارد؛ سیاست تغییرکرده در تب باز در بازخوانی دقیقه‌ای یا focus/open بعدی دیده می‌شود.

## تنظیمات ظاهر

افزونهٔ نصب‌شده صفحهٔ مستقل «چت پانته ← ظاهر»، هشت متن و هشت رنگ و بازنشانی مستقل دارد. گزینهٔ ظاهر schema=2 و runtime همچنان schema=2 است؛ هیچ SQL یا n8n برای این تغییر لازم نیست. توضیح ثابت نگهداری به درخواست کاربر در 0.4.0 حذف شد؛ سیاست سروری و تأیید clear حفظ شده‌اند. GET عمومی و بدون cache فقط ظاهر مجاز را می‌دهد و fallback اولیه محفوظ است. صفحهٔ واقعی مدیر با هشت ورودی رنگ و nonce بدون افشای کلید render شد. Chrome تولید در سه اندازه، دریافت ظاهر تازه و تاریخچه، یک widget و کنترل‌های قابل دسترس را با صفر خطای runtime تأیید کرد؛ هیچ پیام یا تماس مدل در این دور تولید انجام نشد. [طرح و شواهد](../../../../specs/003-chat-appearance/).

## رابط فعال در 0.4.0

ورودی با ارسال آیکونی داخلی و focus سایه‌دار، label فقط برای صفحه‌خوان، حذف توضیح ثابت به درخواست کاربر، چهار لینک اختیاری در ظاهر و بستن با history/کلیک بیرون اضافه شده‌اند. schema ظاهر ۲ با مهاجرت حفظ‌کنندهٔ متن/رنگ است؛ public appearance همان نسخهٔ ۱ با فیلد افزایشی links. ابعاد panel حفظ شده‌اند. نگهداری سروری و تأیید clear تغییر نکرده‌اند. نسخهٔ رسمی نصب و ۱۲ فایل با ZIP/منبع برابر شدند. تنظیمات اتصال و کلیدها، متن/رنگ مدیر و سیاست واقعی حفظ شدند؛ صفحهٔ native مدیر چهار جفت متن/URL دارد و option ظاهر غیرautoload است. Chrome تولید با TLS معتبر در سه اندازه، ابعاد دقیق، ورودی جدید، Back نخست/دوم و بستن بیرون را با صفر خطای runtime تأیید کرد؛ هیچ ارسال پیام یا تماس مدل در این دور تولید انجام نشد. [طرح و شواهد](../../../../specs/004-widget-composer-shortcuts/).

## اصلاح چیدمان در منبع 0.4.1

عرض دکمهٔ تنها/فرد و خوشامد، مرکز ارسال، سمت پیام‌ها و فاصله‌گذاری اصلاح شده‌اند. تنها فیلد نام ارسال از فرم ظاهر به انتخاب کاربر حذف شده؛ مقدار قدیمی برای دسترس‌پذیری حفظ می‌شود. schemaها و تمام تنظیمات محفوظ‌اند. نسخهٔ نصب‌شده تا تأیید ارتقای جدید همان جدول بالاست؛ [درخواست و شواهد](../../../../specs/005-chat-layout-polish/).
