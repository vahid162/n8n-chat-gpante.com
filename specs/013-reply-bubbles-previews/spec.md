# حباب‌های مستقل، ویژگی خطی و تصویر محصول

درخواست کاربر: پیشنهادها و پیام‌های متوالی مانند پیام‌رسان حباب مستقل داشته باشند؛ جدول ویژگی با فهرست خطی جایگزین و تصویر کوچک سمت راست عنوان/زیرعنوان محصول قرار بگیرد. افزونه 0.7.0 و مهارت 0.9.0؛ Main 1.3.0 ثابت می‌ماند.

- عنوان مستقل Markdown/شماره‌دار، متن، مشخصات و CTA یک پیشنهاد در یک حباب گروه می‌شوند؛ پیشنهاد بعد و متن مستقلِ مقدمه/جمع‌بندی حباب جدا دارند. پیام ساده با پاراگراف مستقل، مرز روشن می‌گیرد. هر turn ذخیره‌شده همان یک turn می‌ماند؛ پیام/هزینهٔ تازه ساخته نمی‌شود. مرزبندی ساختاری است، نه تشخیص معنایی یا حدس مشخصات.
- حباب‌ها فاصلهٔ ۱۰ پیکسل، مرز و گوشهٔ روشن دارند؛ دستیار چپ و کاربر راست است. ویژگی‌ها ul/li و هر مشخصه در یک خط با قلم ۱۳ هستند؛ جدول‌های فعلی مدل و تاریخچه نیز هنگام render تبدیل می‌شوند. داده/متن آرشیو و پرامپت مدل تغییر نمی‌کند. جدول مقایسهٔ چندستونی نیز نام ستون‌ها و مقدارها را حفظ می‌کند؛ جدول نامعتبر/بزرگ متن می‌ماند.
- تصویر تزئینی ۴۸×۴۸ کنار راست عنوان و توضیح، از thumbnail واقعی همان محصول عمومی می‌آید؛ عنوان و عکس از مدل پذیرفته نمی‌شوند. متن کوتاه زیرعنوان از توضیح همان بخش است. عکس بارگذاری تنبل و اندازهٔ رزروشده دارد؛ عکس ناموجود/خراب حذف بصری می‌شود و متن/دکمه می‌مانند. خوشامد تمام‌عرض و رنگ‌ها/ابعاد/سربرگ قبلی حفظ می‌شوند.
- bridge فقط `products: [{url,title,thumbnail}]` افزایشی را در send و assistant history می‌سازد. user metadata و metadata خام backend کنار گذاشته می‌شوند. لینک دقیق canonical، انتشار، نبود رمز، product اصلی و visible/catalog/search دوباره بررسی می‌شوند. تصویر فقط raster محلیِ uploads با URL معتبر است؛ هیچ URL دلخواهی از سرور fetch نمی‌شود. CDN خارجی، SVG، query/fragment و مسیر پیمایشی پذیرفته نیستند.
- cache فقط در همان request، برای موفق/ناموفق، و سقف ۳۰ lookup مستقل است؛ این سقف کارِ نمایش است و پوشش کاتالوگ را محدود نمی‌کند. شکست تصویر/metadata پاسخ متنی موفق را خراب نمی‌کند. یک عکس فقط به حبابِ دارای دقیقاً یک لینک منطبق متصل می‌شود؛ بخش مبهم عکس محصول دیگری نمی‌گیرد.
- REST v1، runtime/appearance schema=2، policy v2، بودجه، مدل، n8n و SQL تغییر نمی‌کنند؛ endpoint جدید، تنظیم جدید و کپی transcript در WordPress لازم نیست. قرارداد قدیمی بدون metadata هنوز قابل نمایش است. embed از منبع بازسازی و ZIP نسخهٔ تازه منتشر می‌شود.

اعتبارسنجی: parser/HTML/URL/فیلد مجاز، عمومی‌بودن و bounds، send/history، Chrome/Firefox در چهار اندازه، عکس راست عنوان، فاصله، لینک ۴۴پیکسلی، Tab/reload و عکس خراب؛ native WordPress/PHP 8.3 برای تصویر واقعی، با chat مصنوعیِ intercept و بدون تماس مدل. سپس Release رسمی/۱۲ فایل/تنظیمات/نسخه‌های workflow پس از نصب تطبیق داده شوند. Safari و دستگاه واقعی جدا گزارش می‌شوند.
