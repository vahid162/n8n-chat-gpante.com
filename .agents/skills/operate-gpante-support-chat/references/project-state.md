# وضعیت جاری پروژهٔ چت جی‌پانته

ثبت: ۲۰ اکتبر ۲۰۲۶. مرجع: [مخزن پروژه](https://github.com/vahid162/n8n-chat-gpante.com). وضعیت n8n در ادامه ثبت تاریخیِ آخرین کار عملیاتی است؛ در مرحلهٔ ساخت افزونه هیچ تغییر یا اجرای تولید انجام نشد.

## تصمیم‌های جاری کاربر

- محصول همهٔ کاتالوگ مجاز عمومی را پوشش می‌دهد؛ سقف ۳۰/۵۰ محصول یا مجموعهٔ پایلوت ندارد.
- مدل DeepSeek موجود، بودجهٔ ۲ دلار در ماه UTC و تاریخچهٔ ۳۰روزه حفظ می‌شوند؛ ترافیک هم‌زمان هنوز معلوم نیست.
- دستور جدید، ساخت افزونهٔ پایهٔ وردپرس در همین مخزن، قابل ارتقا و با Ponytail/Spec Kit را مجاز کرد. منع قدیمی «ساخت افزونه نباشد» برای این بسته جایگزین شده است.
- **نصب یا تغییر gpante.com، قالب و افزونه‌های نصب‌شده و انتشار Main مجاز نشده و انجام نشده‌اند.** آزمون‌ها روی نصب جداگانهٔ محلی با backend مصنوعی اجرا شدند.
- نمایش عمومی برای همهٔ بازدیدکنندگان است؛ محدودیت «فقط مدیر» وجود ندارد. نصب تازهٔ افزونه خاموش است تا مدیر اتصال آماده را روشن کند.

## افزونهٔ پایهٔ وردپرس — ساخته و محلی بررسی شد

منبع واحد `wordpress-plugin/gpante-support-chat/` با نسخهٔ **۰٫۱٫۰** شامل loader استاندارد، Settings API، bridge/catalog بازاستفاده‌شده، template، asset و uninstall است. افزونه framework، جدول، سرویس یا updater سفارشی ندارد. `integration/wordpress/bridge.php` و `catalog.php` فقط loader سازگاری‌اند؛ asset و template کپی مستقل ندارند. embed اختیاری وودمارت با `scripts/build-widget.cjs` از همین منبع تولید می‌شود.

گزینهٔ خصوصی `gpante_support_runtime` با `schema_version=1`، nonautoload و show_in_rest=false حفظ می‌شود. فقط manage_options و nonce هسته اجازهٔ ذخیره دارند؛ کلید در HTML بازنمایش ندارد، ورودی خالی آن را حفظ می‌کند و sanitizer idempotent است. migration در activation و init اجرا می‌شود؛ فیلدهای موجود حفظ می‌شوند. نسخهٔ schema آینده حفظ و runtime ناسازگار متوقف می‌شود. deactivation داده را نگه می‌دارد؛ uninstall فقط option خودش را حذف می‌کند.

Origin دقیق HTTPS از home_url معتبر وردپرس، شناسه‌ها از کوکی امضاشده و REMOTE_ADDR و مقصد ثابت از کد می‌آیند. هیچ URL دلخواه یا کلید مرورگری اضافه نشده است. قرارداد API v1، نام workflowها، مدل، budget و دیتابیس n8n تغییر نکرده‌اند.

### شواهد این مرحله

- **۴۰ آزمون Node**، تست تنظیمات/مهاجرت PHP، تست امنیت bridge و **۸ حالت query** موفق؛ lint PHP و WPCS **۳٫۴٫۱** بدون خطا یا هشدار.
- WordPress **۷٫۱٫۳**، WooCommerce **۱۱٫۲٫۱**، PHP **۸٫۴٫۲۵** و MariaDB **۱۱٫۴** در محیط جداگانه: نصب خاموش، nonautoload، منع مشترک، nonce نامعتبر، حفظ کلید/فیلدها، schema آینده، غیرفعال/فعال‌کردن و uninstall بررسی شدند. کاتالوگ واقعی hidden/private/passworded را حذف، visible/catalog/search و قیمت صفر را حفظ و شمار کل صفحهٔ خارج محدوده را درست برگرداند.
- **agent-browser ۰٫۳۹٫۱ و Chrome ۱۵۵٫۰٫۸۰۵۹٫۸۴ نصب و واقعاً اجرا شدند**؛ دسکتاپ ۱۴۴۰×۱۰۰۰، موبایل عمودی ۳۹۰×۸۴۴ و افقی ۸۴۴×۳۹۰، ارسال، خطا/retry، history reload، reset، Escape، نبود کلید در DOM و یک رابط بدون تکرار موفق‌اند. خطای runtime مرورگر صفر بود؛ خطای HTTP مصنوعی عمداً آزموده شد.
- سه ایراد با شواهد واقعی رفع شدند: قیمت WooCommerce پیش از JSON از نوع stdClass است؛ Settings API می‌تواند sanitizer را دوباره صدا بزند؛ Chrome هنگام غیرفعال یا مخفی‌شدن کنترل فعال، focus را به body می‌برد. مشکل بریدگی پنجره در ارتفاع کوتاه نیز با scroll پنجره رفع شد.
- بستهٔ `gpante-support-chat-wordpress-0.1.0.zip` فقط ۱۰ فایل runtime دارد و با WP-CLI روی همان نصب محلی نصب/جایگزین شد؛ تنظیم فعال و schema=1 حفظ شدند. این ZIP با ZIP مهارت Codex متفاوت است.
- Spec Kit رسمی ۱٫۱٫۳ در مخزن راه‌اندازی شد؛ نیازها، plan، قرارداد و tasks در `specs/001-wordpress-plugin-basic/` و constitution در `.specify/memory/` قرار دارند. [گزارش کامل بررسی](../../../../specs/001-wordpress-plugin-basic/verification.md).

**محدودیت:** آزمون روی نسخه‌های مشخص بالا و قالب پیش‌فرض محلی بود؛ WoodMart تولید، همهٔ نسخه‌های حداقل، Safari/iOS واقعی، multisite و اتصال به n8n زنده در این مرحله بررسی نشده‌اند. هیچ تماس پولی مدل انجام نشد. Main بنا بر آخرین ثبت عملیاتی غیرفعال باقی است؛ برای نصب تولید هنوز اجازه و بررسی provider، HTTPS، proxy/IP، cache و timeout لازم است.

نسخهٔ جاری مهارت canonical **۰٫۴٫۰** است و نصب محلی به همین checkout پیوند دارد. مهارت/بستهٔ Codex با WordPress plugin ۰٫۱٫۰ مستقل‌اند؛ ZIPهای قدیمی خودکار به‌روز نمی‌شوند. ثبت این مرحله ادامهٔ شاخهٔ `feat/support-chat-v1` و PR پیش‌نویس شمارهٔ ۱ است؛ PR ادغام یا آمادهٔ انتشار اعلام نشده است. خود ثبت Git، نصب تولید یا فعال‌کردن Main نیست. وضعیت head در checkout بعدی بازخوانی شود.

## تکمیل آماده‌سازی ورک‌فلو — ۲۰ اکتبر

گراف زندهٔ هر دو ورک‌فلو با منبع ثبت‌شده برابر بود؛ تنها تفاوت تنظیمات اولیه با نامزد خصوصی، `availableInMCP=true` بود و حفظ شد. پشتیبان تازه بیرون مخزن عمومی ثبت شد. اعتبارسنجی activation نصب‌شده، SDK strict و کامپایل Code برای Main و Retention موفق و بدون هشدار بود.

فقط تنظیمات Retention برای نگهداری نتیجه/خطای اجرای تولید به `all` تغییر کرد. خروجی این گراف، timestamp و شمار حذف است؛ محتوای گفتگو وارد اجرای آن نمی‌شود. منبع سازنده و JSON عمومی بازسازی شدند؛ JSON Main دقیقاً بدون تغییر ماند. سپس Retention با MCP رسمیِ متصل به همین n8n و بدون restart منتشر شد؛ active=true و activeVersionId بازخوانی شدند.

دو اجرای صریحِ نسخهٔ منتشرشده موفق بودند: `12159` با حذف صفر و `12160` با حذف یک fixture منقضی. در آزمون دوم، پیام مصنوعی ۳۱روزه حذف و پیام جدید حفظ شد؛ fixture باقی‌مانده نیز پاک شد. هر دو اجرا mode=trigger دارند ولی با درخواست ابزار آغاز شده‌اند؛ شاهد نوبت خودکار ساعت نیستند. به‌دلیل فعال‌شدن ذخیرهٔ نتیجه، بررسی نوبت خودکار بعدی از executions امکان‌پذیر است.

هیچ تماس مدل جدیدی انجام نشد. هفت تماس و هزینهٔ محافظه‌کارانهٔ `0.0044808 USD` ثابت ماندند؛ رزرو نامعلوم وجود نداشت. Main همچنان غیرفعال و nodes/connections/settings آن بدون تغییر بودند. اثرانگشت هر ۱۵ ورک‌فلوی نامرتبط با ابتدای همین مرحله برابر ماند و schema چت همچنان فقط در `project_db` بود. سایت، قالب، افزونه‌ها و سرویس مشترک تغییر نکردند.

ثبت Git این مرحله شامل تنظیمات/قالب Retention، README و مهارت نسخهٔ ۰٫۳٫۲ با مراجع نگهداری است و ادامهٔ همان PR پیش‌نویس شمارهٔ ۱ در شاخهٔ `feat/support-chat-v1` است. پیش‌نویس محلی رابط جدا می‌ماند. هنگام ثبت، وضعیت Main/Retention و دو اجرای موفق `12159` و `12160` دوباره از n8n بازخوانی شدند؛ اجرای طبیعی دیگری در آن مشاهده نبود. این ثبت Git هیچ انتشار تازهٔ n8n یا تغییر سایت انجام نمی‌دهد.

## تغییرات این مرحله

وب‌هوک دارای Header Auth جای Chat Trigger عمومی را گرفته است. شناسهٔ نشست/IP باید فقط در کد سروری سایت تولید شود. بارگذاری/پاک‌کردن تاریخچه، کنترل ظرفیت و نرخ، lease و کنترل هزینه در دیتابیس پروژه پیاده شده‌اند. چهار دور ثابت مدل، قبل از هر تماس رزرو و بعد از پاسخ تسویه دارند. خروجی آخر فقط response عمومی است و state داخلی به مرورگر نمی‌رود.

بودجه با BIGINT نانودلار، ماه UTC و رزرو ۰٫۳۲ دلار/تماس اعمال می‌شود. هزینهٔ معتبر از usage با نرخ اوج بدون cache حساب می‌شود؛ خطا یا usage نامشخص رزرو را مصرف‌شده نگه می‌دارد. قیمت تا `2026-11-18T00:00:00Z` اعتبار دارد؛ پس از آن تماس تازه تا بازبینی تعرفه متوقف می‌شود. حذف ردیف تنظیم بودجه نیز fail closed است. این سقف به مصرف سامانه‌های دیگر روی کلید مشترک مربوط نیست.

پیش‌فرض مهندسی فعلی: دو درخواست هم‌زمان سراسری، یک درخواست فعال/نشست، شش پیام و ۳۰ عملیات/دقیقه بر شناسهٔ IP سرور، چهار تماس مدل، خروجی ۱۵۳۶ توکن، پیام ۴۰۰۰ نویسه و اجرای ۱۵۰ثانیه‌ای. این‌ها پاسخ به ترافیک نامعلوم‌اند و SLA محسوب نمی‌شوند.

تاریخچهٔ بیش از ۳۰ روز هرگز خوانده نمی‌شود؛ شش نوبت اخیر زمینهٔ مدل است. Retention برای حذف فیزیکی مستقل از ترافیک منتشر شده است. reset نمی‌تواند با ذخیرهٔ پاسخ جاری رقابت کند. ذخیرهٔ اجرای خام Main خاموش است؛ Retention نتیجه/خطای تولیدِ فاقد متن گفتگو را برای نگهداری ثبت می‌کند.

کد کاتالوگ جدید، وضعیت publish، نبود رمز و visible/catalog/search را با فیلترهای AND رعایت می‌کند. schema و ترتیب قیمت بومی WooCommerce بازاستفاده شده‌اند. alias کنترل‌شدهٔ جعبه/باکس و term واقعی «MDF یا پلکسی» اضافه شده؛ ترکیب «و» متفاوت باقی است. `price_asc` روی منبع اعمال می‌شود. پوشش تولید محدود نشده ولی خروجی هر ابزار bounded و خطای بیش‌ازحد بزرگ صریح است.

`wordpress-plugin/gpante-support-chat/` منبع جاری کد نصب‌شدنی است و فقط در WordPress محلی نصب شد. اتصال تولید، هویت پراکسی و تنظیم خصوصی سایت هنوز اعمال نشده‌اند. چسباندن JavaScript در HTML به‌تنهایی این backend را ایجاد نمی‌کند.

## شواهد واقعی و حدود آن‌ها

- ۳۵ آزمون Node روی منبع یکپارچه موفق شدند: ابزار عمومی، مرزهای ورودی، پاسخ امن، رزرو/usage مدل و رندر متن/لینک. پنج آزمون VM شاخهٔ واقعی مرورگر، ارسال/تلاش مجدد/reset/timeout/فوکوس را پوشش دادند؛ این جای مرورگر واقعی نیست. آزمون‌های PHP پل سروری و هشت حالت callback کاتالوگ با query/Schema مصنوعی و lint موفق بودند.
- activation نصب‌شده و SDK strict برای Main ۶۶نودی و Retention دونودی، موفق با هشدار صفر؛ Codeها کامپایل شدند. این بررسی روی کپی خصوصی دارای اتصال است، نه قالب عمومی فاقد Credentials.
- migration و تست‌های دیتابیس ابتدا در یک تراکنش rollback بررسی شدند و سپس ارتقای schema اختصاصی اعمال شد. تست نبود تنظیم بودجه ابتدا خطا را نشان داد، بعد از اصلاح تابع موفق شد. آزمون SQL شامل رزرو یکتا، منع refund دوباره/رزرو پس از مصرف نامعلوم، سقف مالی، ظرفیت، جداسازی، reset و انقضای تاریخچه است و fixtureها rollback شدند.
- آزمون واقعی Native Agent اولیه با ابزار قوانین موفق بود: دو تماس مدل. مسیر HTTP جدید چهار سناریوی واقعی گذراند: تأیید نام مصنوعی، یادآوری در همان نشست، ندانستن نام در نشست دیگر، و اعلام صادقانهٔ ناتوانی خواندن provider جدیدِ اجرا‌نشده. زمان اجرا حدود ۶ تا ۱۱ ثانیه بود. مثبت‌بودن جست‌وجوی محصول روی provider جدید هنوز بررسی نشده است.
- در مجموع هفت تماس مدل، هزینهٔ محافظه‌کارانهٔ `0.0044808 USD` در دفتر پروژه ثبت کردند. همهٔ usageهای مسیر جدید در SQL تسویه شدند. این هزینه و شمارش مخصوص زمان ثبت‌اند.
- آزمون ظرفیت بدون مدل: ۱۶ admission با هشت worker، دقیقاً دو پذیرش و ۱۴ رد ظرفیت؛ بیشینهٔ زمان شامل Docker حدود ۱۵۹ میلی‌ثانیه. این تست SLA یا آزمون بار مکالمهٔ مدل نیست؛ fixtureهای آن پاک شدند.
- چهار ورک‌فلوی Validation با CLI رسمی آرشیو و غیرفعال بودنشان بازخوانی شد. ۱۵ ورک‌فلوی نامرتبط پس از import با اثرانگشت پیش از تغییر برابر ماندند. سرویس مشترک restart نشد.
- callbackهای provider با آزمون ثبت‌شدهٔ `tests/catalog-query.php` و query/Schema مصنوعی بررسی شدند؛ این بررسی، اجرای WordPress/WooCommerce یا Schema واقعی نیست. مرورگر واقعی در مرحلهٔ افزونهٔ محلیِ بالا بررسی شد؛ تولید هنوز بررسی نشده است. آزمون Store API قدیمی، شاهد تکمیل eligibility منبع جدید نیست.

جزئیات فنی، توابع، تعرفه و مسیر بازسازی در [workflow-v1.md](workflow-v1.md) نگهداری می‌شوند. مرجع پشتیبان و رسیدهای خصوصی خارج از مخزن عمومی است. نسخهٔ JSON عمومی، پشتیبان کامل قابل بازیابی نیست.
