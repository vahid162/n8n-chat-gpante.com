# کد اتصال سایت — مرحلهٔ نهایی

این پوشه افزونهٔ وردپرس یا بستهٔ قابل نصب نیست. طبق تصمیم کاربر، هیچ افزونه‌ای نصب نمی‌شود و اتصال سایت با کد در آخرین مرحله انجام خواهد شد. فایل‌ها فعلاً فقط در مخزن هستند؛ روی gpante.com بارگذاری یا اجرا نشده‌اند.

- `bridge.php`: کنترل درخواست مرورگر، کوکی امضاشدهٔ HttpOnly/Secure/SameSite، شناسهٔ IP سمت سرور و فراخوانی مسیر ثابت n8n. کد PHP باید روی سرور سایت اجرا شود؛ قرار دادن آن در HTML یا Custom Code مرورگر کافی نیست.
- `catalog.php`: دو endpoint عمومیِ محدود برای محصولات مجاز و راهنماها؛ بدون دسترسی مدیریتی و فایل فروشی. این provider باید قبل از آزمون نهایی ابزارهای نسخهٔ ۱٫۱ در سایت اجرا و با نسخهٔ WooCommerce نصب‌شده تطبیق داده شود.
- `assets/chat.js` و `assets/chat.css`: رابط فارسی/RTL بدون وابستگی خارجی. متن با DOM امن نمایش داده می‌شود؛ فقط لینک عمومی معتبر سایت قابل کلیک است.

کد bridge، `catalog.php` را از همین پوشه بارگذاری می‌کند. روش بارگذاری سروری کد و محل assetها در مرحلهٔ اتصال نهایی تعیین می‌شود. `GPANTE_SUPPORT_ASSET_BASE` باید URL پوشهٔ assetها روی همین سایت باشد. تنظیم خصوصی `gpante_support_runtime` شامل `enabled`، `backend_url` ثابت و `shared_key` اختصاصی است؛ در نبود آن، چت غیرفعال می‌ماند. مقدار واقعی کلید در این مخزن قرار نمی‌گیرد. هیچ activation hook، صفحهٔ مدیریت یا تغییر خودکار قالب وجود ندارد.

قرارداد مرورگر: `POST /wp-json/gpante-support/v1/chat` با `action` یکی از `sendMessage`، `loadPreviousSession` و `resetSession`؛ برای ارسال، `chatInput` نیز لازم است. مرورگر شناسهٔ نشست یا IP معتبر تعیین نمی‌کند. پاسخ موفق به‌ترتیب `{output}`، `{messages:[{role,content}]}` یا `{ok:true}` است.

پیش از اتصال نهایی، HTTPS و cookie، رفتار cache/CDN، هویت واقعی `REMOTE_ADDR` پشت پراکسی، timeoutهای PHP/webserver، API کاتالوگ، موبایل/دسکتاپ و جداسازی نشست‌ها باید روی سایت واقعی آزموده شوند. هدر دلخواه `X-Forwarded-For` منبع هویت نیست. آزمون‌های محلی PHP و Node جای بررسی مرورگر یا WooCommerce واقعی را نمی‌گیرند.
