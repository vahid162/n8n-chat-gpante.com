# نمایش پاسخ‌ها

در نامزد 0.7.0، پیشنهادها/پاراگراف‌های مستقل حباب جدا و مشخصات فهرست خطی دارند. thumbnail کوچک از محصول عمومیِ همان لینک در وردپرس می‌آید؛ متن ذخیره‌شده/مدل/بودجه ثابت است. [سناریو و شواهد جاری](../specs/013-reply-bubbles-previews/verification.md).

## سابقهٔ پاسخ جمع‌وجور 0.5.2

منبع افزونه 0.5.2؛ نسخهٔ رسمی 0.5.2 روی سایت نصب و بررسی شد. اصلاح در CSS، حذف جداکنندهٔ خالی میان لینک‌های مجاز و نسخهٔ بسته است؛ مدل، دادهٔ گفتگو، n8n و قراردادها تغییر نمی‌کنند.

در CSS قبلی، لینک‌ها inline-flex و متنشان 700 بود. فقط تک‌لینک یک پاراگراف به عرض کامل تبدیل می‌شد؛ چند لینک می‌توانستند در یک ردیف قرار بگیرند. اصلاح، همهٔ لینک‌های پاسخ را flex با عرض کامل محتوای والد و وزن 400 می‌کند. چیدمان دو‌ستونی لینک‌های اختیاری خوشامد حفظ می‌شود و فقط وزن متنشان معمولی است.

حباب‌ها padding برابر ۸×۱۱، فاصلهٔ پیام‌ها ۸، پاراگراف‌ها ۶ و سلول‌های جدول ۶×۸ پیکسل دارند. قلم اصلی ۱۴ و جدول ۱۳ پیکسل حفظ شده است؛ ارتفاع خط متن ۱٫۷ و جدول ۱٫۶ است. فضای لمس لینک‌ها حداقل ۴۴ پیکسل، ساختار معنایی جدول، پیمایش صفحه‌کلید جدول عریض، رنگ‌ها، محتوای کامل و ابعاد پنجره حفظ می‌شوند.

## روش بررسی

آزمون اختیاری `tests/chat-presentation-browser.py` با Playwright، در context جدا و با پاسخ مصنوعی فقط در مرورگر اجرا می‌شود؛ متن آزمایشی به n8n یا مدل نمی‌رود. نیاز به Playwright و موتورهای نصب‌شده دارد؛ وابستگی runtime افزونه نیست.

```sh
python tests/chat-presentation-browser.py --url https://gpante.com/ --previews /tmp/public-product-previews.json --evidence-dir /tmp/chat-layout --engines chromium firefox
```

ابزار جاری، `--previews` را به‌صورت آرایهٔ عمومی `[{"url":"https://gpante.com/product/.../","title":"...","thumbnail":"https://gpante.com/wp-content/uploads/...jpg"}]` یا شیء دارای previews می‌خواند؛ این فایل باید دو thumbnail واقعی و معتبر از خروجی WordPress داشته باشد و هیچ کلید/گفتگوی خصوصی نداشته باشد. `--css` CSS و formatter نامزد را فقط در همان مرورگر اعمال می‌کند. همهٔ chat requestها intercept و عکس‌ها از منابع عمومی خوانده می‌شوند. حباب جدا، جدول قدیمی→فهرست، URL/HTML امن، عکس راست عنوان، Tab، عکس خراب و reload بررسی می‌شوند. ابزار با تغییر رابط تکامل یافته؛ نتایج جدول/ArrowLeft زیر، سابقهٔ نسخهٔ 0.5.2 هستند.

## نتیجه و حدود

Playwright 1.64.0 روی Linux با Firefox 157 و Chromium 156 اجرا شد. baseline در هر دو، دو دکمهٔ اول را هم‌ردیف و با وزن 700 بازتولید کرد. کاندیدا در هر دو و چهار اندازهٔ 1440×1000، 390×844، 844×390 و 320×568، لینک‌ها را زیر هم، تمام‌عرض و با وزن 400 نشان داد. جداکنندهٔ خالی میان لینک‌های مجاز، بدون حذف توضیح واقعی یا متن لینک نامعتبر حذف می‌شود؛ فاصلهٔ دکمه‌های متوالی حداکثر ۸ پیکسل است.

جدول نمونهٔ ثابت از حدود ۲۱۱ به ۱۶۸ پیکسل رسید؛ حدود ۲۰٫۴٪ کوتاه‌تر با همان داده و قلم. پنجره در همان چهار اندازه به‌ترتیب 390×650، 374×650، 390×366 و 304×480 باقی ماند. لمس ۴۴پیکسلی، Tab، ArrowLeft جدول عریض، لینک داخل سلول، عدم اجرای HTML/لینک ممنوع و بازیابی پس از reload موفق بودند؛ خطای runtime صفر و پیام واقعی/تماس مدل صفر بود.

۶۸ آزمون Node، PHP تنظیمات/ظاهر/bridge/کاتالوگ، WPCS بدون خطا/هشدار و پنج تست بسته/انتشار گذشتند. Release رسمی پس از موفقیت CI منتشر شد؛ tag/commit، checksum و هر ۱۲ فایل با منبع تطبیق داده و بسته با PHP 8.3/WP-CLI نصب شد. کل runtime، کلیدها، enabled، ظاهر، policy/revision، قالب و افزونه‌های فعال حفظ شدند. فقط cache keyهای همین سایت تازه و فایل بارگذاری موقت حذف شد. Firefox/Chromium روی فایل نصب‌شده همان هشت حالت و reload را بدون خطا تأیید کردند. Chrome موجود نیز سه اندازه، جدول معنایی، دکمهٔ ۴۴پیکسلی، پیمایش جدول عریض و عدم اجرای HTML/لینک ممنوع را با صفر خطای runtime و صفر violation محدود دسترس‌پذیری تأیید کرد. پاسخ‌ها فقط در مرورگر مصنوعی بودند؛ هیچ پیام واقعی/تماس مدل انجام نشد. WebKit به‌دلیل نبود کتابخانه‌های سیستمی میزبان اجرا نشد؛ تغییری در بسته‌های سیستم‌عامل داده نشد. Safari، دستگاه فیزیکی و همهٔ نسخه‌های مرورگر بررسی نشده‌اند. آزمون موتور Playwright روی Linux جای Safari واقعی یا دستگاه فیزیکی را نمی‌گیرد؛ [توضیح رسمی مرورگرها](https://playwright.dev/python/docs/browsers).
