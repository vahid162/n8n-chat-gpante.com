# وضعیت نگهداری پروژه

به‌روز شده در ۲۰ اکتبر ۲۰۲۶. این سند خلاصهٔ عمومی ادامهٔ کار است؛ وضعیت زنده باید دوباره خوانده شود. شناسه‌های استقرار، نسخه‌های فعال، پشتیبان‌ها، دفتر هزینه و رسیدهای عملیاتی خصوصی‌اند و وارد این مخزن نمی‌شوند.

## نسخه و منبع

| جزء | مرجع جاری |
| --- | --- |
| افزونهٔ نصب‌شدهٔ WordPress | **0.2.0**؛ [انتشار رسمی](https://github.com/vahid162/n8n-chat-gpante.com/releases/tag/wordpress-v0.2.0) |
| قرارداد افزونه | `wordpress-plugin/gpante-support-chat/`؛ schema تنظیمات ۲، REST v1 و policy contract ۲ |
| منابع workflow | نسخهٔ 1.2.0؛ `src/` و خروجی قطعی `scripts/build-workflow.cjs` |
| مهارت canonical | همین پوشه؛ **0.5.0**؛ نسخهٔ مهارت از افزونه و workflow مستقل است |
| راهنما | [آرشیو و ارتقا](../../../../docs/conversation-archive.md)، [گزارش تولید](../../../../docs/production-readiness.md) |

کاربر راه‌اندازی و ارتقای همین چت در تولید را مجاز کرده است؛ دستور قدیمی «سایت تغییر نکند» مربوط به ساخت محلی بود. اختیار به قالب، افزونه‌ها یا سامانه‌های نامرتبط گسترش ندارد. دسترسی سرور مستقیم SSH با PHP 8.3 و WP-CLI است؛ از SentinelX استفاده نشود.

## وضعیت تأییدشده

- Main، Admin و Retention منتشر و فعال‌اند. گراف و پارامترهایشان با منابع تطبیق داده شدند. ورک‌فلوهای نامرتبط دست‌نخورده‌اند.
- migration 003 پس از توقف کوتاه Main و تخلیهٔ درخواست‌ها اجرا شد. پیام‌های قبلی، زمان اصلی و دفتر مالی حفظ شدند؛ schema کاربردی فقط در project_db است، نه دیتابیس داخلی n8n.
- پرسش پذیرفته‌شده پیش از تماس مدل ثبت می‌شود؛ پاسخ نهایی، خطا یا وضعیت قطع‌شده برای بررسی مدیر باقی می‌ماند. دادهٔ فنی قدیمی نامعلوم ساخته نشده است. آرشیو مدیر ۳۰ روز از زمان اصلی پرسش است.
- مدیر یک مدت سراسری ۳، ۷، ۱۵ یا ۳۰روزه برای کاربر تعیین می‌کند. پیش‌فرض جاری ۳۰ روز و پاک‌کردن روشن است. پاک‌کردن کاربر فقط دسترسی/زمینهٔ مدل را می‌بندد؛ آرشیو را حذف نمی‌کند. افزایش مدت، متن منقضی یا پاک‌شده را بازنمی‌گرداند.
- «چت پانته ← گفتگوها» فهرست صفحه‌بندی‌شده، جست‌وجو/فیلتر و جزئیات دارد. اتصال مدیریت کلید و نقش مستقل دارد؛ نقش SQL فقط تابع ثابت مدیریت را اجرا می‌کند. اجرای خام Main و Admin خاموش است و پیام در WordPress کپی نمی‌شود.
- ZIP رسمی، checksum و ۱۱ فایل نصب‌شده تطبیق داده شدند؛ schema=2، کلید قبلی و enabled حفظ شدند. کش فقط همین سایت پاک شد. کلید مدیریت خصوصی تنظیم و صفحهٔ واقعی مدیر بدون نمایش کلید render شد.
- مرورگر واقعی تولید: پاسخ واقعی، جداسازی دو بازدیدکننده، دکمهٔ خاموش و رد درخواست مستقیم clear، بازیابی پس از reload و حفظ سؤال/پاسخ در آرشیو پس از پاک‌کردن موفق بودند. سه اندازهٔ دسکتاپ/موبایل و صفر خطای runtime ثبت شدند.
- آزمون صریح نگهداری، fixture منقضی را حذف و آرشیو جدید را حفظ کرد؛ دفتر مالی تغییر نکرد. اجرای دستی به‌دلیل saveManualExecutions=false در history باقی نماند؛ نتیجه از دیتابیس تأیید شد. اجرای طبیعی ساعتی پس از استقرار نیز موفق مشاهده شد.
- ۴۴ آزمون Node، تست‌های SQL در محیط جدا و CI، PHP settings/bridge/catalog، lint/WPCS، پنج تست بسته/انتشار و WordPress/Chrome واقعی محلی موفق بودند. [شواهد تفکیک‌شده](../../../../specs/002-conversation-archive/verification.md).

اصلاح کاتالوگ stdClass نسخهٔ 0.1.1 حفظ شده است. بررسی کامل کاتالوگ و قیمت در مرحلهٔ قبلی ثبت شد؛ این ارتقا قرارداد کاتالوگ، مدل و محدودیت‌ها را تغییر نداد.

## ادامهٔ نگهداری

1. Git، نسخهٔ نصب‌شده، سیاست معتبر، نسخهٔ فعال سه workflow و اجراهای Retention را تازه بخوانید. 003 فقط یک‌بار اجرا می‌شود؛ restore نباید منطق قدیمی حذف فیزیکی را بازگرداند.
2. پشتیبان‌ها و رسیدهای خصوصی خارج از checkout عمومی‌اند. پشتیبان دارای transcript نباید آرشیو دائمی بسازد؛ سیاست سرویس پشتیبان خارجی باید جدا بررسی شود.
3. بودجهٔ تأییدشده ۲ دلار/ماه تقویمی UTC و محدودیت‌های قبلی حفظ شده‌اند. پیش از انقضای تعرفه، نرخ/context واقعی دوباره بررسی شوند؛ صرفاً تاریخ تمدید نشود.
4. سفارش، دانلود خریداری‌شده و ارجاع انسانی هنوز ساخته نشده‌اند؛ به نیاز و احراز هویت/مالکیت جداگانه نیاز دارند.

Safari/iOS واقعی، multisite، همهٔ نسخه‌های حداقل و بار گسترده بررسی نشده‌اند. ارسال دوباره پس از گم‌شدن پاسخ شبکه ممکن است request/هزینهٔ تازه بسازد؛ idempotency منطقی ارسال هنوز اضافه نشده است. حذف فیزیکی تا یک نوبت ساعتی تأخیر دارد؛ سیاست تغییرکرده در تب باز در بازخوانی دقیقه‌ای یا focus/open بعدی دیده می‌شود.
