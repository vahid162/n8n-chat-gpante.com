# درخواست چندابزاری و تشخیص خطای پاسخ مدل

هدف: پاسخ معتبر DeepSeek صرفاً به‌خاطر داشتن چند فراخوانی ابزار رد نشود و علت واقعی رد پاسخ‌های نامعتبر، بدون ذخیرهٔ payload خصوصی قابل بررسی باشد.

- کل batch پیش از اجرا بررسی شود: یک تا سه فراخوانی در ظرفیت باقی‌ماندهٔ سه ابزار، نام‌های فعلی، ID معتبر/یکتا و آرگومان رشته‌ای محدود.
- ابزارها به‌ترتیب اجرا شوند؛ هر ID دقیقاً نتیجهٔ خودش را بگیرد و تا پایان صف تماس تازهٔ مدل انجام نشود. invalid_query یک ابزار مانع رسیدگی به ابزار معتبر بعدی نیست.
- سقف چهار تماس مدل، سه ابزار در کل پرسش، دو درخواست هم‌زمان، بودجهٔ ماهانهٔ ۲ دلار، رزرو/تسویه و timeoutها ثابت بمانند. پس از مصرف سقف، مدل فقط پاسخ نهایی بدهد.
- رد پاسخ فقط کد ثابت فنی تولید کند؛ متن provider، آرگومان، نام ناشناخته، هدر یا خطای خام در diagnostics ذخیره نشود. error_code موجود در آرشیو ۳۰روزه استفاده شود؛ raw execution storage خاموش بماند.
- اصل خطای مدل با تسویهٔ ناموفق از بین نرود؛ پاسخ موفق بدون تسویهٔ تأییدشده همچنان منتشر نشود.
- افزونهٔ 0.4.2، قالب، SQL، کلیدها، policy و ورک‌فلوهای دیگر تغییر نکنند. خطاهای قدیمی بدون شاهد خام به علت تازه منتسب نشوند.
