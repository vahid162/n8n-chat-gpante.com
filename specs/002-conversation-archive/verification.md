# شواهد نسخهٔ 0.2.0

۲۰ اکتبر ۲۰۲۶؛ نسخهٔ 0.2.0 در محیط آزمون و سپس تولید بررسی شد؛ شواهد این دو مرحله جدا ثبت شده‌اند.

- ۴۴ آزمون Node؛ قرارداد عمومی، ورودی محدود مدیریت، جداسازی گراف، سیاست دکمه، انقضای DOM، retry و focus.
- آزمون SQL روی دیتابیس جدا: migration از schema اصلی با timestamp قدیمی، چهار مرز مدت، حفظ آرشیو پس از clear، عدم بازگشت پیام، admission پیش از مدل، خطا/قطع‌شدن و پایان یکتای request، صفحه‌بندی ۲۰+۵، فیلتر، نقش محدود و عدم تغییر دفتر مالی. داده‌ها مصنوعی و transaction آزمون rollback شد؛ بودجهٔ زنده دست‌کاری نشد.
- WordPress واقعی محلی با WP-CLI: ارتقا از 0.1.1، حفظ enabled/کلید و schema=2؛ HTTP واقعی نقش مدیر/مشترک، nonce نامعتبر، تعارض revision، نمایش آرشیو با چت خاموش و escape متن script.
- Chrome واقعی صفحهٔ مدیر: انتخاب ۱۵ روز و خاموش‌کردن clear، ذخیرهٔ مرکزی، نمایش متن مخرب بدون اجرا و اعمال سیاست در رابط عمومی موفق شد.
- Chrome واقعی: ارسال و لینک، بازیابی، خطا/retry، پاک‌کردن و Escape، سه اندازهٔ 1440×1000، 390×844 و 844×390؛ خطای runtime صفر. backend این مرحله مصنوعی است.
- PHP settings/bridge/catalog، lint، WPCS و پنج آزمون بسته/انتشار. ZIP فقط ۱۱ فایل runtime دارد؛ مهارت، تست، پشتیبان و کلید همراه آن نیست.
- اعتبارسنجی نامزد Main و Admin با n8n نصب‌شده: activation و SDK strict و کامپایل Code؛ صفر هشدار.

Safari/iOS واقعی، multisite و بار گسترده بررسی نشده‌اند. idempotency منطقی ارسال پس از گم‌شدن پاسخ شبکه همچنان ساخته نشده است؛ ثبت یک request ID دوبار انجام نمی‌شود ولی ارسال تازه می‌تواند request تازه باشد. حذف فیزیکی تا یک نوبت ساعتی تأخیر دارد. تغییر سیاست در تب باز حداکثر در بازخوانی دقیقه‌ای یا focus/open بعدی دیده می‌شود؛ سرور همواره سیاست جاری را اعمال می‌کند.


## تولید

- PR و CI موفق ادغام شدند؛ Release immutable دانلود و checksum و هر ۱۱ فایل runtime با منبع و نصب واقعی تطبیق داده شدند.
- migration 003 پس از تخلیهٔ Main اجرا شد؛ fingerprint متن‌ها/زمان قبلی، runtime و ledger حفظ شدند. سه workflow فعال و گراف‌هایشان با منبع مطابق‌اند؛ schema چت در دیتابیس داخلی n8n نیست و ورک‌فلوهای نامرتبط تغییر نکردند.
- کلید مدیریت مستقل در تولید تنظیم شد؛ درخواست بدون کلید و با کلید عمومی رد شد. WordPress واقعی صفحهٔ مدیر را با schema=2 و بدون نمایش کلید render کرد.
- Chrome روی gpante.com: یک پرسش واقعی و پاسخ در آرشیو ثبت شدند؛ نشست دیگر به آن دسترسی نداشت. خاموش‌کردن clear، دکمه را مخفی و درخواست مستقیم را با 403 رد کرد. پس از بازگرداندن تنظیم و پاک‌کردن، تاریخچهٔ کاربر خالی و سؤال/پاسخ در آرشیو مدیر باقی ماندند. نمایش جزئیات در WordPress نیز بررسی شد.
- هر سه اندازهٔ صفحه و صفر خطای JavaScript تأیید شدند. پیش‌فرض نهایی ۳۰ روز و clear روشن است؛ سقف هزینه افزایش نیافت.
- fixture مصنوعیِ منقضی با اجرای صریح Retention حذف و آرشیو جدید حفظ شد؛ ledger تغییر نکرد. اجرای دستی طبق تنظیم ذخیره نشد؛ نتیجه با خواندن دیتابیس تأیید شد. اجراهای طبیعی ساعتی پس از استقرار نیز موفق بودند.

کلید، متن مشتری، شناسهٔ نشست/اجرا و رسیدهای کامل در Git عمومی ثبت نشده‌اند. آزمون روزهای نگهداری در دیتابیس جدا با زمان مصنوعی انجام شد؛ تاریخ پیام واقعی کاربران دست‌کاری نشد.

## اصلاح راهنمای بسته در 0.2.1

ارجاع قدیمی فایل نصب و توضیح مبهم پاک‌کردن در readme بسته اصلاح شد. Release جدید immutable پس از CI موفق دانلود، checksum و هر ۱۱ فایل با منبع و نصب واقعی تطبیق داده شدند. ۹ فایل اجرایی دیگر byte-for-byte با 0.2.0 برابرند؛ منطق افزونه و backend تغییر نکرد. کل option، کلیدها، enabled و سیاست حفظ و صفحهٔ عمومی با asset نسخهٔ 0.2.1 تأیید شد. تماس مدل اضافی برای این اصلاح متنی انجام نشد.
